# Agent Note：执行器位置的工作区授权

状态：已实现

[English](2026-09-08-workspace-grant-at-the-executor.md) | 中文

## 问题

运行准入会在消费断言 nonce 之前解析工作区授权，并检查租户、设备、撤销和继承。继承来的文件系统或 Shell 操作运行时，却没有任何东西使用授权的根目录或模式。因此，一次有效运行可以使用授权外的路径、在授权撤销后继续使用，或在只读授权下写入。

这个缺失的判定不能由 Debian 控制面完成。根目录是签发设备上的路径，只有该设备能按操作实际使用的文件系统语义解析大小写、符号链接、junction、别名和缺失后缀。

## 决定

`dsh-sandbox` 声明可选的 `ctx.workspaceAuthority` 服务，供其强制执行的文件系统与 Shell Consumer 使用。`dsh-workspace-grant-execution` 为 Candy 提供该服务。它在每次工具分发时解析唯一开启的运行，只把运行的租户、设备和授权标识放入异步执行上下文。

文件系统执行器在每次读取或变更前重新读取授权。它按原生 realpath 语义解析现有祖先目录，要求目标落在一个当前根目录下，并拒绝 `read-only` 下的写入。Shell 执行器在前台执行前重新读取授权，要求工作目录落在当前根目录下，并把既有沙箱模式收紧到授权上限。后台启动使用同一次工具分发所解析的授权，因为继承来的 `start` 操作是同步的。

外层工具监听器只建立身份，不是强制点。继承来的执行器会在触及文件系统或启动进程的操作位置调用授权。通过这些 Provider 的直接或替代工具路径会抵达同一检查。

## 结果

已撤销或收窄的记录会在当前分发的下一次执行器操作生效。解析到授权根目录之外的链接或 junction 就是越界路径。子运行得到与父运行相同的授权 id，准入仍会拒绝手工铸造且指名另一授权的子运行，因此执行器检查不能放宽父授权。

Candy 没有得到第二套文件系统、Shell、沙箱或 Windows 传输。它向现有 DSH 能力实现贡献授权。没有装载 `dsh-workspace-grant-execution` 的组合仍有准入检查，但没有本地根目录强制检查。

生成的能力与 Cordis 目录把 `ctx.workspaceAuthority` 归类为 `dsh-sandbox` 接缝，把 `dsh-workspace-grant-execution` 归类为 Candy 实现，并把继承的文件系统与 Shell 包归类为 Consumer。这样，服务声明发生变化时，所有权边界会默认拒绝漂移。

进程沙箱的读取可见性仍由平台实现负责。本改动约束进程工作目录和文件效应模式，但不解析 Shell 源码，因为命令解析器会成为可绕过的第二套 Shell 策略。更强的进程读取边界需要能在正常启动运行时的同时执行该限制的平台沙箱。

## 考虑过的替代方案

**在 `tools/pre-execute` 检查工具名和参数。** 拒绝，因为直接文件系统 Consumer、复合工具和 Shell 语法都能绕过参数检查。判定属于执行操作的 Provider。

**把规范路径放进执行断言。** 拒绝，因为 Debian 无法解析 Windows 文件系统身份，而一个已签名字符串不能证明操作运行时 junction 或别名实际指向什么。

**建立 Candy 专用文件与 Shell 操作。** 拒绝，因为 DSH 已拥有这些能力及其 Windows 实现。通用授权服务让 Candy 增加租户判定而不复制它们。

## 验证

本包测试驱动真实的 `dsh-fs-sandbox` Provider，覆盖已授权访问、跨租户与跨设备记录、只读拒绝、分发期间撤销、未知会话、越界路径，以及符号链接或 Windows junction 逃逸。变异负控制会停用只读检查，确认对应拒绝测试失败后再恢复实现。
