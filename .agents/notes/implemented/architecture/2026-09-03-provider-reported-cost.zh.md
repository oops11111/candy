# Agent Note: 提供方已经开出的那张账单

Status: implemented

[English](2026-09-03-provider-reported-cost.md) | 中文

## Problem

`RunBudget` 在 token、挂钟时间、金额与并发四个维度上为一次运行设界。其中三个都可以从 harness 已有的东西里量出来。金额不行：`TokenUsage` 没有成本字段，`packages/` 里没有任何东西为 token 定价，而包的 README 把这一点记成了一条限制 —— 需要调用方自行为 token 定价来回答。

这个说法是错的，而证据就在为本仓库录制的一份夹具里。Claude CLI 的终止帧携带 `total_cost_usd`，而 `ClaudeCliFrameTranslator` 读了那一帧、用了它的 token 计数，却把紧挨着的成本丢掉了。租户真正被计费的那个数，每一次运行都在到达，却在离它被需要之处只有一行的地方被丢弃。

## Decision

`TokenUsage` 增加可选的 `costMicroUsd`，而 Claude CLI 的翻译器用 `total_cost_usd` 填上它。

### 只报告，不推导

这个字段只携带提供方声明过的数值，别无其他。适配器不会从价目表算出一个来，因为算出来的数与报告来的数无法区分，而在任何合约不是标价的部署里它都是错的 —— 并且错在要花钱的那个方向。

这让「缺席」变得有含义：它是「未报告」，而不是零。录制夹具里一次失败的运行报告 `total_cost_usd: 0`，而这个零是一个真实的事实 —— CLI 为一次每个请求都被拒绝的运行计费为零。把缺席的字段读成零的消费方，会少算每一个保持沉默的提供方，因此有一个测试把两者钉开。

### 整数微美元，只转换一次

CLI 报告的是浮点美元；`RunBudget` 计的是整数微美元，因为用浮点比较或扣减的上限会漂移。因此取整只发生一次，在 `mapUsage` 里，也就是浮点数抵达的地方。不是有限非负数、或缩放后会越出安全整数范围的成本会被略去而不是被夹取：被修补过的数值会像 CLI 报告过它一样被计到租户头上。

### 是整次调用，而不是它旁边的那些计数

`total_cost_usd` 覆盖 CLI 运行过的每一个模型，包括它为自己发起的辅助调用 —— 一次只有两个 token 的录制请求还计入了一次 `claude-haiku-4-5` 调用，而该帧按模型统计的总量之和恰好等于所报告的数值。这正是租户要付的钱，所以它才是预算该用的那个数；字段文档也写明它是提供方对这次调用的总额，而不是同一个对象里那些计数的价格。

## Consequences

`RunBudget.costMicroUsd` 在唯一报告成本的那条路由上可强制。这是一个比「成本核算已经工作」更小的主张，而 README 说的正是这个：HTTP 路由什么也不报告，因此对着它计费的调用方仍要自行为 token 定价。

成本无需任何新事件就进入了会话日志。它搭乘 `TokenUsage`，而 `assistant/chunk` 与 `assistant/message` 本来就携带它，因此一次运行的计费总额免费地成为持久且可重放的。目前还没有任何东西把它折叠成一个累计值 —— `dsh-token-meter` 的 `tokenUsage` 投影汇总的是 token 桶，要加入金额就得提升它的 state 版本并加宽它的客户端视图，那是一个另带客户端界面的独立决定。

成本只在最后到达。只有终止帧会报告一个，因此一次在流中被杀掉的运行，无论花了多少都不报告成本。`maxBudgetUsd` 仍然给这样的运行封顶，因为上限是由 CLI 强制的，而不是由它报告的内容强制的。

## Alternatives considered

**把成本留在 `dsh-llm` 之外，从 CLI 相关的包里暴露它。** 这会让金额不进入一条大多数适配器都填不上的缝隙。予以否决，因为从某一个适配器伸出的旁路正是这条缝隙存在所要防止的：任何通用消费方 —— 预算、计量表、用量视图 —— 都无法在不知道自己在跟哪个提供方说话的情况下读到它。

**携带提供方的浮点数，在每个消费方处再转换。** 在适配器那边更简单，在别的每一处都更糟：每个消费方都要重复取整，而两个取整方式不同的消费方会对「这次运行花了多少」给出两个答案。

**为不报告成本的提供方按价目表推导一个。** 那会让这个字段始终存在，并且一致地没用：推导出的数值与报告来的无法区分，因此没有任何消费方能分辨哪些数字来自提供方。价目表是一项部署事实，它属于配置价格的地方，而不属于适配器内部。
