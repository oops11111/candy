# Agent Note: Candy 执行断言

Status: implemented

[English](2026-09-02-candy-execution-assertions.md) | 中文

## Problem

[Candy 运行时边界](../../../../docs/candy-runtime-boundaries.zh.md) 要求 Candy 运行时在调度工作之前校验控制平面断言的签发方、受众、过期时间、租户、账户、会话、设备、工作区授权与 nonce,并忽略或拒绝客户端在请求本身中给出的任何租户或账户。如果没有一个被拥有的机制,未来每一条调度路径都会各自重新推导这项检查,而混淆代理规则就只会存在于碰巧记得它的那个调用点上。[控制平面标识符](2026-09-02-candy-control-plane-identifiers.zh.md) 命名了这些实体,却没有携带任何证明一次运行归属于谁的手段。

## Decision

`@deepseek-ai/dsh-execution-assertion`(`packages/control-plane/execution-assertion`)签发并准入按运行的凭据。`mintExecutionAssertion(claims, secret)` 为控制平面的决定签名;`admitExecutionAssertion(token, secret, expectation, now)` 返回已校验的声明,或一组封闭拒绝原因中的一个——`malformed`、`unsupported-version`、`signature`、`issuer`、`audience`、`not-yet-valid`、`expired`、`lifetime`。

**混淆代理规则由参数列表强制执行。** `ExecutionAssertionExpectation` 只命名 `issuer`、`audience` 与 `maxLifetimeMs`。它没有用户、设备、账户、工作区授权、对话、会话或运行字段,因此不存在任何参数能让调用方断言这次运行属于谁;身份只会在签名校验之后,包含在被准入的声明中离开本模块。这就是把规则强制执行在做出该决定的操作之中,而不是依赖一个直接调用方可以绕过的门面。

**格式遵循仓库内先例。** 令牌为 `v1.<base64url 载荷>.<base64url HMAC-SHA256>`,即 [`dsh-client-connection` 浏览器会话 cookie](2026-08-24-browser-token-authentication.zh.md) 已经使用的形状与 32 字节密钥下限。MAC 覆盖收到的载荷文本,因此准入过程从不对解码后的对象重新序列化,JSON 键顺序也无法改变被签名的内容。载荷与签名都必须是规范 base64url;两者都通过往返比较解码,签名比较先检查长度,再进行常数时间比较。签名在读取任何声明之前完成校验。

解码后的载荷被当作 wire 边界而非同进程类型化值处理:每一项声明都检查存在性与类型,id 必须是非空字符串,时间戳必须是非负安全整数。`now` 是参数而非对 `Date.now()` 的读取,因此调度器可以针对自己已持有的时间戳进行准入,测试也无需控制时钟。

本包以参数形式接收签名密钥,不拥有任何持久内容。它没有 Cordis 服务、没有凭据提供方依赖,也没有重放存储。

## Alternatives considered

**只校验声明,把真实性留给后续的验证器。** 这是改动更小的方案,但予以拒绝:一个安全性依赖于尚不存在的验证器的声明校验器是半个机制,而一句"请先验证"的文档注释在直接调用方可以跳过时并不构成强制执行。签发与准入一同落地,使该模块无法以未经认证的方式被使用。

**使用 JWT 库。** JWT 会带来一个解析器、一个算法协商字段,以及本凭据并不需要的一整套规范选项,而 `alg` 混淆的处理将成为我们要审计的内容。仓库已经为浏览器会话做过一次这个选择;遵循该先例可以只审查一种令牌形状而不是两种,而这个依赖大约只能删掉四十行代码,却会引入大得多的攻击面。

**使用非对称签名,使运行时无法签发。** 这是更强的拆分,而它落败的真实原因是:密钥分发——谁持有私钥、如何轮换、运行时如何获知公钥——属于尚未构建、且当前没有消费者的控制平面工作。HMAC 与今天实际存在的信任安排相匹配:一个控制平面及其自有的运行时。该限制已记录在包 README 中。

**在此处用模块内的重放集合强制 nonce。** 予以拒绝,因为单次使用的强制执行需要按租户划分、带过期的持久状态,而这属于调度器。纯模块中的内存集合会在跨进程与重启时静默失效,却看起来像一道重放防线。

**把它放进 `dsh-control-plane`,与 id 并列。** 予以拒绝:id 包对外宣称的是一套无外部依赖的词汇,把加密与 wire 格式机制折叠进去,会让一个包拥有两个变更理由,并把 `node:crypto` 强加给每一个 id 消费者。

## Consequences

Candy 的调度路径现在拥有一次把令牌变成运行身份的调用,并且没有任何一次调用会从请求中接受身份。拒绝原因为运维诊断而区分,但其中每一个都会拒绝该次运行,因此调用方无法重试进入更弱的检查。单元覆盖固定了每一种拒绝、在保留原签名的情况下篡改某项声明、由另一密钥签发的令牌、生存期的精确边界,以及最后一个可准入的毫秒。

边界页面归于断言的两项属性在这里并未交付,二者都已记录在包 README 中:准入不会消费 nonce,因此在调度器拥有的重放存储出现之前,断言可在其生存期内被重放;签名密钥在凭据保险库工作落地之前是一个不受管的参数。由于该方案是对称的,进行准入的运行时同样可以签发;在一个控制平面拥有自有运行时期间这是可以接受的,而在运行时由控制平面并不信任其签发的一方运营之前,必须重新审视这一点。
