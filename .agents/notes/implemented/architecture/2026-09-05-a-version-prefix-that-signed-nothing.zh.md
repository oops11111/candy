# Agent Note: 什么都没签的版本前缀

Status: implemented

[English](2026-09-05-a-version-prefix-that-signed-nothing.md) | 中文

## Problem

一个执行断言的形式是 `v1.<载荷>.<签名>`,而这个前缀带着一条被写下来的保证:将来声明集发生变化时要签发 `v2`,而不是重新解读 `v1`。

而签名只覆盖了载荷。一次探测签发了一个令牌,并用两种方式重算 HMAC:

`{"signatureMatchesPayloadOnly":true,"signatureMatchesVersionAndPayload":false}`

于是这个前缀只是一段签名数据块前面未经认证的文本。只覆盖载荷的签名在任何前缀之下都能通过校验,这意味着那条注释所陈述的保证并不是这套构造能给出的:一旦出现 `v2` 声明集,一个被改标为 `v1` 的 `v2` 令牌就会通过校验,随后被 `v1` 的读取者解码——正是版本本该阻止的那种重新解读。

今天并不存在 `v2`,因此当下没有任何可利用之处。当下错的是:一条安全契约被写了下来却没有被强制执行,而且发生在那个专职判定"这次运行属于谁"的模块里。

## Decision

MAC 覆盖 `${version}.${payload}`。签发时签入它所打上的版本,准入时按它所收到的版本校验,因此一个面向后来声明集的读取者所校验的签名,把它自己的前缀也包含在内。

分隔符就是令牌本就使用的那一个。两段都是 base64url,因此它不可能出现在任一段之内,也就不需要长度前缀来保证边界不可伪造。

令牌格式发生了变化,而预发布阶段的立场允许这一点:由更旧的构建签发的令牌不再通过校验,而这里所签的断言只存活一分钟。

## Consequences

版本前缀现在名副其实。有一个测试直接钉住了它:一个签名只覆盖载荷而不含版本的令牌会被以 `signature` 拒绝,而不是被准入。

反向对照并不精准,这一点值得说明。测试辅助函数按模块的方式构造令牌,因此还原构造会让每一个由辅助函数构造的用例连同这个绑定测试一起失败。真正隔离出该性质的是那个绑定测试。

`dsh-client-connection` 的浏览器会话 cookie 使用同样的 `v1.<body>.<签名>` 格式——本模块正是借用了它——并且只签 body。那个包不在本计划范围内,有自己的消费者与威胁模型,因此这里只作记录,不随本次一起改动。

## Alternatives considered

**等到 `v2` 出现再说。** "不要为假设而建造"这条规则针对的是抽象与选项,而不是一个已经没有覆盖到读取者据以行动的字段的 MAC。代价只是一次字符串拼接,而写下 `v2` 的那一刻,旧令牌已经在路上了。

**去掉版本前缀。** 那是取消这条虚假承诺,而不是兑现它,并且在声明集变化时不留任何区分手段——那样迁移就完全没有标记可依。

**给各段加长度前缀。** `runtime-pool` 的键那样做,是因为它的字段是可能包含分隔符的不透明字符串。这里的不会:base64url 里没有 `.`,因此边界本就不可伪造。
