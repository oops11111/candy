# Agent Note: A run that ended and kept spending

Status: implemented

[English](2026-09-05-a-run-that-ended-and-kept-spending.md) | 中文

## Problem

计量通过请求所面向的那个会话来找到运行：该会话没有运行，就意味着这个请求不归本运行时计费，于是它原样通过。对于一个本运行时从未为之开过运行的会话，这是对的。对于一个其运行已经结束的会话，这是错的。

结算会删除运行记录。租约可能在一个仍在工作的 agent 之下到期 —— 那正是租约存在的理由 —— 而清扫会结算掉那次运行，agent 却继续跑。它的下一个请求找不到记录，看起来像是来自别处的请求，于是未被计量地抵达提供方。针对已启动运行时的一次探查证实了这一点：清扫之后的那次调用返回的是 `{ kind: 'stop' }`，什么也没被记账。那次因为活过租约而被切断的运行，随后免费地跑了下去。

## Decision

调度器记住它结算掉的那些会话，并拒绝它们的调用。

这份记忆在进程里而不在介质上，而这是实质，不是省事。它必须活得比运行久 —— 那时记录已经没了 —— 而不需要活得比进程久，因为那个还可能发起调用的 agent 同样住在这个进程里，并会随它一起消失。一次丢掉这份记忆的重启，早就已经丢掉了那个 agent。

它由 `endedSessionMemory` 设上限，最旧的先被淘汰，因此长命的运行时持有的是一个有界的集合。被淘汰会话的调用会重新原样通过：上限界定的是运行时持有多少，而一个旧到会被淘汰的会话，其 agent 几乎肯定已经随它的运行一起走了。这一点被明说出来，而不是留作意外。

在一个曾经结束过的会话上开启的新运行会把它清掉，因此一个被控制平面复用的会话会重新被计量，而不是被永远拒绝。

## Consequences

一个请求可能处于的三种情形现在彼此分明：从来不是我们的、是我们的且开启中、是我们的且已结束。只有中间那种会被记账，也只有第一种会原样通过。

这件事没有做到的是让 agent 停下来。调度器不持有任何 agent，也不持有任何进程；拒绝它的模型调用就是这一层能做的全部，而一个已经被启动的提供方进程会一直跑到启动它的那一方去收割它为止。

## Alternatives considered

**保留已结算的运行记录，而不是删除它。** 那样查找就能找到它并直接拒绝，不需要第二个结构。恢复会重新驱动每一条携带已结算数字的记录，而「恰好一次」的标记只覆盖每个出资方最近的一次结算，因此活得比自己结算更久的记录会在下一次启动时被重复记账。删除，正是让恢复得以成立的东西。

**销毁驱动该会话的那个 agent。** 那是移除调用方而不是拒绝它，也是「一次运行驱动一个会话」最终应有的含义。`close` 可能从 agent 自己的驱动链内部被调用，而从内部销毁一个拥有它的 fiber，正是 initiator 作用域备注已经记录过的那个风险。它需要编排接合点，以及一个带真实循环的组合测试；而拒绝那次调用两者都不需要。

**拒绝任何没有开启中运行的会话请求。** 一条规则代替三种情形，而它会让本运行时成为进程里每一次模型调用的裁判 —— 包括一个部署自己的非 Candy 工作，以及属于另一个共享同一介质的运行时的会话。
