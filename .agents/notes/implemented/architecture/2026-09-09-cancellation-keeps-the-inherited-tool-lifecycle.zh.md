# Agent Note: 取消保持继承的工具生命周期

Status: implemented

[English](2026-09-09-cancellation-keeps-the-inherited-tool-lifecycle.md) | 中文

## 问题

Harness 已经把调用方的取消信号传播到正在运行的工具，等待已经开始的主体达到静止状态，把结果规范化为 `ABORTED`，随后发布唯一一条最终 `tools/result`。Candy 增加了一个会被等待的工具授权审计观察器，却没有真实组合测试证明该观察器为租户受管运行保留了这些生命周期保证。因此 R3 清单仍把经过 Candy 运行的工具与事件流记为未验证。

## 决定

继续由继承的 `dsh-tools` 运行时拥有执行与事件。在 `dsh-run-scheduler` 增加 Loader 组合测试：开启一条真实 Candy 运行，为该运行的会话执行一个有作用域的 Harness 工具，在主体启动后取消，并刻意保持主体清理未完成。

测试要求原始信号抵达主体；清理被卡住期间，执行 Promise 与 `tools/result` 事件都保持等待；最终结果携带 `ABORTED`；恰好一条终止结果事件与该结果相同；Candy 为该受管运行恰好保留一条允许授权审计。它检验的是 Candy 实际观察的工具事件流；Remote Gateway/WebSocket 传输仍是继承的 DSH 工作，其租户绑定部署属于 R5。

## 后果

R3 取消现在已经为受委派子运行、提供方进程与流、计量取消、工具，以及工具执行所发出的最终事件提供组合证据。Candy 没有新增工具运行器、取消控制器、事件总线或远程流实现。

把工具主体临时变异为与取消信号竞争，会让执行在清理完成前返回，并使新测试在等待状态断言处失败。恢复继承的等待后，测试重新通过。

## 考虑过的替代方案

**增加 Candy 工具包装器。** 未采用，因为它会重复 DSH 执行能力，并形成一层可绕过的生命周期外观。

**把授权审计当作终止工具事件。** 未采用，因为授权发生在主体之前；它说明执行能否开始，而不是执行与清理是否已经结束。

**在这里构建 Remote Gateway 取消。** 未采用，因为远程传输属于 DSH 职责，而 Candy 对它的租户／设备绑定是 R5 工作。
