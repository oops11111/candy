# Agent Note: 一个设置页，以及它周围的什么都不做

Status: implemented

[English](2026-09-09-a-settings-page-and-nothing-around-it.md) | 中文

## 问题

Candy 的服务商账户 API 没有界面。租户可以拥有账户，但只有带着会话 Cookie 的脚本才能创建、校验或撤销它。

诱人的答案是做一个 Candy 网页应用：自带外壳、自带导航、自带配色的页面。这三样仓库里都已经有了，就在设置面板里——它存在的理由恰恰是让拥有整页的功能不必再造一遍。所以真正的问题不是要做什么，而是不做什么。

有一件事确实需要判断。现有的每个设置页都通过 `ctx.remote`（dsh 的 `/api` 载体）读取数据——而那个载体鉴别的是**进程启动令牌**，Candy 的路由鉴别的却是通过 OAuth 回调设置的会话 Cookie 所标识的**浏览器用户**。它们是同一来源上的两个不同权威，页面若顺手去拿熟悉的那个，问的就是关于「谁在调用」的错误问题。

## 决定

一个 `settings.section` 贡献，`packages/client/ui-settings-candy-account`，除此以外什么都不加。没有外壳，没有导航，没有主题，没有响应式框架，没有第二套 Web 界面：这些面板全都提供，而 section 的样式表只使用主题已经声明的 `--dsw-alias-*` 记号。

页面直接使用同源 HTTP，**不注入任何 Remote 命名空间**。它的 `inject` 是 `['slots', 'locale']`——它真正读取的两个服务。注入 Remote 会让页面等待一个它从不使用的传输，也会暗示 Candy 的路由和 dsh 载体是同一个权威。

`src/client/api.ts` 是页面唯一携带权威的地方：它发送会话 Cookie，并在每次写入时把 CSRF Cookie 回显到 `x-candy-csrf`，这正是 `dsh-control-plane-api` 检查的那一对。CSRF Cookie 缺失时发送的是空头部而不是补出来的值——缺失的令牌和过期的令牌从信封那里得到的是同一个回答，在这里伪造一个只会把这件事藏起来。

状态机上的三个决定：

**失败是状态，不是异常。** 每个操作都让 store 落定并正常返回。唯一可能 catch 的调用方是组件，而这里的组件不持有自身状态；页面渲染发生了什么，而不是由点击处理函数决定。

**会话结束是被响应的，不是被报告的。** `401` 会清空身份、名单和打开的表单——那些行属于一个已经不存在的会话，把它们留在屏幕上只会诱发一次落不了地的点击。其余任何失败都保留屏幕上的内容并提供重试。

**没能送达的请求，措辞就是「没能送达」。** 凭据校验回答「不可用」和请求根本没到达控制面是两件不同的事；混为一谈会在网络出问题时告诉租户他的凭据坏了。

任何可能移动其他行的改动之后都会重读名单：把一个账户设为默认会清掉另一个的标记，删除一个会提升出替代者，而没有哪个单独的回答说明哪一行动了。凭据校验只报告一行，因此不重读。

`order: 5` 把页面排在「模型」之前。一次运行记在哪个服务商账户上，先于它请求哪个模型被决定。

## 影响

租户可以在自己本来就在用的面板里管理自己的服务商账户，两种随发语言都有，整页在六十三个用例下达到按文件 100% 覆盖：传输层的状态码映射与 CSRF 回显、状态机的重读与登录失效规则、页面的渲染与每一次点击、注册的 slot 注入与 fiber 释放，以及样式表的记号与手机宽度换行。

凭据端到端只进不出，测试把这一点钉住：创建表单是唯一持有它的字段，是关闭了自动填充的 `password` 输入框，表单关闭时被清除，传输规格断言发出去的密钥不出现在任何返回内容里。

本次没有加入的：没有管理员查看其他租户账户的视图（API 也没有），没有分页，登录失效后无法就地恢复——登录入口是一次整页跳转——也没有 Candy 的部署组合。页面作为客户端插件登记在工作区中；没有任何随发 bundle 挂载它，因为还没有 bundle 组合 Candy 的 Host 插件。

## 考虑过的替代方案

**做一个 Candy 网页界面。** 被任务书和代码同时否决：面板已经拥有外壳、导航、主题和响应式布局，第二套界面意味着四样东西要跟着一样东西同步。

**通过 `ctx.remote` 访问账户。** 否决：该载体鉴别的是进程启动令牌，不是浏览器用户。让 Candy 的路由能被它触达，等于给那个载体第二个权威，这与会话 Cookie 存在的意义正好相反。

**把页面状态存进设置文档。** 否决：这些都不是偏好设置。账户属于控制面，而且设置传输在非 loopback 页面上本就被禁用——每一个 Candy 部署都是非 loopback。

**新增一个 `danger` 按钮变体。** 否决：共享按钮有四个变体，面板里别处的破坏性操作用的是给 ghost 变体上色的类名。为一个页面加第五个变体，是为私有需求改动共享原语。

**把已删除账户渲染成墓碑行。** 读过领域实现后否决：`listProviderAccounts` 隐藏已删除记录、保留已撤销记录，这个划分本来就是对的——已撤销的账户解释了某个服务商为何停止工作，已删除的则已经不在了。API 自己的文档注释与此相反，已一并更正。
