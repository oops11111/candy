# Agent Note: 租户状态不是系统 CLI 登录

Status: implemented

[English](2026-09-09-tenant-state-is-not-a-system-cli-login.md) | 中文

## 问题

账户页列出了 Claude CLI 和 Codex CLI 账户，但没有摘要说明当前租户是否拥有可用凭据。读取 `claude auth status`、`codex login status` 或任一工具的默认主目录，回答的是另一个问题：Unix 服务用户是否已向环境中的 CLI 认证。在多租户进程中，这个答案不属于任何 Candy 租户，还可能让一个用户的会话看起来可供另一个用户使用。

服务器已经通过已认证路由返回当前租户的无密钥账户列表。每条记录都说明它属于哪个服务商、是否已撤销，以及哪个可用账户是默认账户。这才是 Candy 所有的登录状态。

## 决定

现有 Harness 账户区域从这份列表为 Claude CLI 和 Codex CLI 推导三种状态：存在可用账户时为已配置，只存在已撤销记录时为凭据已撤销，没有记录时为未配置。已配置状态显示租户自己的账户标签。它不暴露凭据、路径、环境变量、端点或其他租户的元数据。

页面明确说明这份摘要不是实时 CLI 校验。Candy 不启动认证命令，不检查服务用户的 CLI 主目录，也不复用其 Cookie 和令牌。针对服务商的实时校验仍是 `dsh-provider-credential-checks` 的扩展；只有 DeepSeek 拥有这个部署所实现的普通 HTTP 检查。

摘要占用现有设置区域，且只使用继承的主题 token 和响应式布局。Candy 不新增设置外壳、手机应用、主题或 CLI 登录流程。

## 影响

运维人员和租户可以区分未配置的 CLI 账户和有意撤销的 CLI 账户，而不会把主机的环境登录当作权限来源。每次创建账户、选择默认账户、撤销或删除后重新读取已认证列表时，摘要都会更新。

组件用例钉住了三种状态和禁止声称共享 CLI 认证的提示。Web 场景通过 Loader 挂载随发浏览器插件，在 1680px 桌面视口和 390px 手机视口下读取同一账户路由，并检查 CLI 摘要在没有水平溢出时仍然可见。把已撤销记录当作活跃记录的变异会使状态用例失败。

这不能证明 CLI 可执行文件已安装，也不能证明已保存的 CLI 凭据能通过认证。Claude 和 Codex 的凭据校验继续回答 `unsupported-provider`，直到有针对服务商、会脱敏的校验被注册。运行时路由是否可用属于部署问题，不得从账户记录推断。

## 考虑过的替代方案

**运行每个 CLI 的原生状态命令。** 否决：如果没有先把命令绑定到租户的隔离池和凭据，它就会读取服务用户的环境状态，跨越该页面所要表达的归属边界。

**把每个已保存的 CLI 凭据都称为已配置且就绪。** 否决：已撤销记录不可用，而账户记录不能证明部署挂载了对应的运行时路由或安装了其可执行文件。

**构建独立的 CLI 设置页或手机视图。** 否决：Harness 设置区域和响应式面板已经提供了所需的扩展点和视口行为。
