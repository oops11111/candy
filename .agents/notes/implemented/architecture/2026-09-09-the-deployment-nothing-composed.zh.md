# Agent Note: 没有任何东西组合出来的那个部署

Status: implemented

[English](2026-09-09-the-deployment-nothing-composed.md) | 中文

## 问题

Candy 的控制面是九个包，加上零个部署。每个包都有自己的 Loader 组合测试，每个测试组合它所需的那两三行；没有任何东西把它们全部组合起来。计划笔记在四个不同的地方这么写着——「还没有部署挂载它」「随发的部署组合……仍未构建」——而账户页在上一次发布中带着同一句自陈交付。

这个缺口不是一个缺失的文件。组合正是那些没有单个包能回答的问题被回答的地方：当继承的 base 把存储路由到别处时，控制面的记录落在哪个介质上；账户 API 封存所用的密钥是不是运行时打开所用的那一把；运维必须提供什么；以及当他们什么都没提供时会发生什么。

## 决定

`packages/bundle/candy-app` 是 `dsh-web-app` 之上的一个补丁层，且不带任何字面量。每一个在不同安装之间不同的值——公开来源、身份提供方、密钥、数据库、池根目录——都是 `!!js process.env.CANDY_*`。写死了来源的 bundle，是一个必须先编辑才能运行的 bundle，而被编辑过的 bundle 就不是被测试过的那个产物。

这个选择让「配置错误的行为」是白得的而不是造出来的：未设置的变量解析为 `undefined`，读取它的那一行在加载时拒绝。十一个用例正是钉住这一点，每一个都点名必须做出拒绝的那个条目——没有这一点，一次因无关原因崩溃的启动也能让用例通过。

**只为一个 domain 插入 SQLite。** 继承的 base 把存储路由到 JSON 后端，它没有 compare/exchange，读取也来自打开时的快照。把断言 nonce 恰好花掉一次，是一次必须在键已存在时失败的写；而第二个 Candy 进程必须看见第一个进程写下的内容。`routes` 把 `candy_control_plane` 送到 SQLite，让继承的会话 domain 留在为它们调优过的后端上。

**一个密钥版本喂给两行。** 账户 API 封存凭据，运行时打开它。用运行时打不开的版本封存的凭据，是一个租户配置了却没有任何运行能使用的账户，而两者之间没有任何东西会报告这件事。

构建这一层暴露了各个包自身无法暴露的一处缺陷：**`RunScheduler` 导出了一个没有任何东西绑定的 `Config` schema。** 没有 `static Config`，所以 Loader 一项都没校验——`issuer`、`audience`、`credentialKeyVersion` 和 `poolBase` 全是 `required()`，也全都没被强制；schema 里的每个默认值都是死的，旁边是十二个读取点各自的 `?? 字面量`。一个 `audience` 缺失的运行时本会启动，并接受寄给任何人的断言。现在 schema 是 `static Config`，构造函数为直接构造的调用方通过它解析，十二处兜底已经删除：默认值只活在 schema 里。

## 影响

一个 Candy 部署就是一个产物加一套有文档的环境。十五个用例通过真实的 Loader 启动已发布的补丁文件——`loadOverlayPatches` 读它，Loader 针对真实的进程环境求值它的 `!!js` 表达式——叠在 `dsh-base` 与 `dsh-web-app` 提供的各行之上。关于这个组合，测试文件里没有任何重述，因此一行被改名或一个变量被拼错会在那里失败，而不是在运维的首次安装时。

其中包括：store、调度器和凭据检查注册表都在；账户路由在没有会话时回答 `401`，来自其他授权方时回答 `403`，而登录在同一个授权方上回答 `303`；通过组合出的 store 花掉的 nonce 第二次被拒绝，这正是 SQLite 路由在起作用；以及十一个变量逐一移除时，启动都停在读取它的那个条目上。

变异确认这些用例承载着规则：解绑 `static Config` 并去掉构造函数的解析，会让十五个中的十个失败，其中包括四个拒绝用例。

本次没有加入的：没有 systemd unit、Nginx 站点、健康检查端点、备份或回滚流程——发布中面向运维的那一半是下一个切片，它将针对这一层的变量清单来写。这里无法配置退役凭据密钥，因为单个变量表达不了一个列表。也没有任何东西阻止两个运行时进程共用同一个 `CANDY_RUNTIME_AUDIENCE`。

## 考虑过的替代方案

**把部署的值写进补丁。** 否决：已发布的产物会在每次安装时与被测试的那个不同，而且部署的密钥会落进一个因其他原因被读取的文件。

**把所有 domain 都路由到 SQLite。** 否决：继承的会话 domain 是为 JSON 后端调优的，它们没有任何地方需要原子交换。为了不点名一个 domain 而更换正常工作的代码脚下的介质，是一个更大的改动。

**给这一层自己的配置 schema，由它来校验环境。** 否决：每一行都已经声明了自己需要什么，在它们前面再放一个 schema，就是同一条规则的第二处落点——而这一处正是没人会更新的那份副本。

**保持 `RunScheduler` 原样，在 README 里把变量记为必需。** 在组合测试提出要求的那一刻就被否决：README 拒绝不了一次启动，而没有任何东西强制的「必需」，正是这个 bundle 存在所要消除的那个形状。
