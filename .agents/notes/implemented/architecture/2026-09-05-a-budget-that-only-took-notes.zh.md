# Agent Note: A budget that only took notes

Status: implemented

[English](2026-09-05-a-budget-that-only-took-notes.md) | 中文

## Problem

Candy 的预算机器在两端都是完整的，中间却是空的。

`admitRun` 拒绝一次额度已经用光的运行，`reserveChild` 把子运行的授予额度从它父运行那里扣掉，而 `RunLedger.charge` 报告一次运行已经完全用尽了哪些维度。最后那份报告本该就是强制执行点，却没有任何东西在读它。`charge` 在仓库里恰好只有一个调用方：它自己的测试。

于是一次以一千 token 被准入的运行可以流出一百万。账本会如实记录它，结算会为此向租户计费，而准入与结算之间没有任何一步会拦下它。边界页要求子运行不得超出其父运行的 token、时间与成本授权；而那份授权只在门口被强制执行，之后再无处执行。

## Decision

`dsh-run-metering` 为一次开启中的运行包裹一条提供方流，而 `RunScheduler.meter` 把它绑定到那个运行时的账本以及它的持久计费上。

三件事会提前结束一次调用，每一件都表现为一个终止的 `error` finish，而不是抛出的异常，因为 `dsh-llm` 缝隙向消费方承诺的是恰好一个终止块，而异常不是其中之一：运行未开启、运行已经什么都不剩，或者这次调用跑过了运行尚存的挂钟时间。

拒绝是在抵达提供方之前读出来的，而这个顺序正是要点所在。一条流至多携带一次用量，而且通常靠近末尾，因此一次已经花光的运行否则会把整次调用做完，再从那个恰好把钱花掉的块里得知自己负担不起。先读剩余额度，才把「一次已耗尽的运行感到意外」变成「一次已耗尽的运行不再发起调用」。

出于同样的理由，计费落在终止块抵达消费方之前：agent 循环一看到 finish 就会索要下一次调用，而事后才施加的计费会让它多做一次调用。组合测试通过在消费 finish 的那个循环内部读取账本，把这个顺序钉住。

一次切断结束的是这次调用，不是那次运行。记录仍然开着，带着这次调用消耗掉的东西，于是启动这次运行的一方来决定：报告这次耗尽、申请更多额度，还是结算。计量器保证的是工作会停下来。

金额只在提供方报告了账单的地方移动。提供方什么都没说时 `TokenUsage.costMicroUsd` 是缺失的，而缺失不等于零：在这里从价目表推导一个数字，会与真正被报告的数字无法区分，而且在部署合约不是标价的任何地方都是错的。

## Consequences

预算现在会停下工作。一次已耗尽的运行的下一次调用根本到不了提供方，而一次跑过其运行所剩挂钟时间的调用会被切断，并且它已经消耗掉的东西已经被记上账。

`RunScheduler.meter` 让这一切成为持久的：计费在这次调用的终止块被交付之前就抵达该次运行的记录，因此两次调用之间的一次重启不丢失任何东西，而第二次调用是针对第一次被量出来的。

三条限制是明确陈述的，而不是暗含的。一个不发出任何东西就卡住的提供方不会被切断，因为挂钟时间是在块抵达时检查的 —— `dsh-run-ledger` 的租约才是界定被遗弃运行的东西，而本包界定的是话多的那种。一条流只报告一次用量，因此过长的单次回复只有在它结束时才被量出来。而针对同一次运行并发计量的两次调用，都是针对谁都还没记过账的那份额度起步的，因此调用彼此重叠的运行，每条流可能超出一次调用的量。

目前还没有任何东西把计量器接进 agent 循环。要做那件事，需要模型请求上带一个 run id，而那与启动审计记录一直在等的归属信息是同一个东西，也不属于本备注。

## Alternatives considered

**改为在 `RunLedger` 里拒绝这笔计费。** 那是超支最先可见的地方，而在那里拒绝恰恰是那个包所反对的：提供方已经开了账单，而一个拒绝记录这笔花费的账本，会报出一份该运行已经用掉的额度。报告 `exhausted` 并由某个调用方据此行动，本来就是那份设计；本次提供的正是那个调用方。

**在运行负担不起一次调用时抛异常。** 更短，而且会打破 `dsh-llm/invariant` 在每一条提供方流周围强制执行的「恰好一个终止块」保证。消费方本来就会处理一次失败的调用；它并不会处理来自一个异步迭代器流中途的异常。

**在计量器内部用定时器检查挂钟时间。** 那样连沉默的流也能切断。它同时也把一个时钟和一条销毁路径放进一个两者都没有的模块，并给每一个测试塞进一个需要停掉的定时器。租约已经覆盖了没有任何东西在驱动的运行。

**按块计费而不是按调用计费。** 那样能界定过长的单次回复。在它背后接着一次持久计费时，那就是每个增量一次介质写入，而对于挂钟切断已经提供的那个界限来说，这是一笔划不来的交易。
