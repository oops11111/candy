# Agent Note: 没有路由接受的令牌

Status: implemented

[English](2026-09-12-a-token-no-route-accepted.md) | 中文

## Problem

设备配对返回 256 位令牌,主机绑定也保存了它,但没有服务端路由接受该令牌。撤销设备只会在其他权威已经铸造断言之后影响运行准入。主机既不能证明已存绑定仍然成立,也无法区分撤销与根本不存在认证协议。

继承的 Remote Gateway 负责 WebSocket 传输、重连和离线状态。在 Candy 中增加另一套连接状态机只会重复该职责,不会让令牌成为权威。

## Decision

`dsh-device-api` 暴露 `GET /api/candy/devices/authenticate`。主机通过 `Authorization: Bearer` 请求头出示设备令牌。有效令牌只返回其 `deviceId` 和 `userId`;缺失、格式错误、未知或已撤销的令牌都收到相同的空 `401`。路由从不返回或记录令牌。已撤销令牌会在 `authenticateDevice` 内保留其设备记录,让租户审计可以记录已撤销主机,同时不向调用方泄露这种区别。

`dsh-device-binding.verify` 向该端点执行一次请求,并确认回复指名的租户与设备完全等于本地保存值。仅当没有本地绑定或服务器返回 `401` 时返回 false。网络失败仍作为错误交给继承的连接所有者,未约定状态或身份不匹配属于协议错误。验证从不释放或替换已存绑定。

这是一条认证协议,不是传输集成。Remote Gateway 在打开或恢复 WebSocket 时仍不会出示令牌;这仍是下一段 R5 集成工作。

## Alternatives considered

**在 API Gateway 内认证。** 本阶段拒绝,因为 Gateway 是 DSH 所有的传输层,也服务于没有 Candy 身份的组合。在注册主机承载尚不存在时改变其通用浏览器 Cookie 规则,会混合设备与浏览器权威,还会让所有既有远程端点同时进入迁移范围。

**收到 `401` 就删除本地绑定。** 拒绝,因为撤销与有意的本地释放是不同操作。自动删除还会让一个临时改写响应的代理获得改变机器下一步可服务哪个租户的能力。

**把所有非 200 响应都当成撤销。** 拒绝,因为部署错误不是授权决定。只有端点约定的 `401` 否认凭据;连接与服务器故障仍是可观察的失败。

## Consequences

配对主机现在拥有一种经过脱敏且可审计的方式,用于测试令牌是否仍然有效;租户撤销会在下一次验证时跨 Candy 进程可见。未知与已撤销凭据在线路上仍无法区分。

主机仍需要调用交换并执行 `bind` 的配对客户端,DSH Remote Gateway 也仍需要一个 Candy 所有的集成,在建连或重连时验证绑定,而不替换其重试和离线机制。
