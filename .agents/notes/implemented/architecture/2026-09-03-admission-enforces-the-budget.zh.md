# Agent Note: 没有任何人查询过的预算

Status: implemented

[English](2026-09-03-admission-enforces-the-budget.md) | 中文

## Problem

`dsh-run-budget` 为一棵委派树可以花费的量设界，而 `dsh-run-admission` 是一次运行从令牌走到被调度调用的唯一路径。两者互不知晓。`RunAdmissionPolicy` 持有一份 expectation、一个密钥、一副 keyring、一个池基准目录，以及两个端口 —— 重放与凭据查找 —— 而任何地方都没有预算。

后果很直白：token、时间或金钱已经耗尽的租户照样被准入。准入校验了断言、消费了 nonce、打开了凭据、解析了池，然后交还一次可以去花这个租户并不拥有的钱的运行。预算算术本身是正确的，却根本没有调用方。

两个包各自都站得住，中间却留了一个洞。真正点名它的是[强制执行规则](../../../../packages/AGENTS.md)：决定要在做出它的那个操作里强制执行，而准入正是一次运行被允许开始的地方。

## Decision

`RunAdmissionPolicy` 增加第三个端口 `findBudget`，`RunRejection` 增加一个 `budget` 阶段。被准入的运行携带它可以花费的额度，因此调用方用 `dsh-run-budget` 对它计费，而不是稍后才发现有上限。

### 缺失的预算意味着拒绝

`findBudget` 返回 `undefined` 是拒绝，而不是许可。预算存储不认识的租户，并不等于额度无限的租户；把缺失的记录当作不计量，会让一次存储故障变成代价最高的那种失败。真正意在不计量的部署，会用一个显式的大额度来表达，那是某个人选定的值，而不是没人填上的空缺。

### 只有可消耗的维度会让运行停下

`hasRemainingBudget` 忽略 `children`，准入也继承了这一点。没有委派名额的运行仍然可以做自己的工作；它只是不能启动子运行。拒绝它会把「不能委派」与「不能继续」混为一谈，有一个测试固定了这个区分。

### 预算在消费 nonce 之前读取

这改变了原先记录下来的顺序，理由值得保留。额度耗尽是这里唯一一种调用方能够修复并重试的拒绝：充值，再出示同一个仍然有效的断言。先消费 nonce 会在一次可恢复的拒绝上烧掉一次性令牌，迫使调用方回到控制面去换一个新断言。而这次预算读取既便宜又不触碰任何密钥，提前做它不花什么代价。

nonce 仍然在凭据之前被消费。它在那里的职责是把并发的重复请求串行化，使同一个令牌的两份副本不可能都抵达密钥；在它前面插入一次读取并不改变这个职责。有一个测试固定了完整顺序 —— 预算、nonce、凭据 —— 因为顺序就是契约；另一个测试断言因预算被拒绝的运行完全不会读取凭据。

## Consequences

`dsh-run-budget` 现在有了消费者，这才使它成为一个组件，而不是一个没人调用的库。这次变更是由编译器强制完成的：新增一个必填端口会让每一个既有调用方报错，直到它们各自提供预算为止 —— 这正是必填字段具备而可选字段不具备的性质。

准入依然只做一次读取、不做写入。它报告一次运行被准入时所依据的额度；它不去扣减，因为扣减是持久写入，而本模块不拥有任何存储。一个在这里读取预算却从不计费的部署，其上限只在准入那一刻成立，而 README 就是这么写的，没有暗示本模块能提供它做不到的强制执行。

这个端口之所以是参数，理由和另外两个一样：这三种存储在本仓库中都不存在，而把它们点名出来，就迫使部署方在运行开始之前先回答预算、重放与凭据查找。

## Alternatives considered

**把缺失的预算记录当作不计量。** 对尚未建好预算存储的部署更简单，但它错的方向是要花钱的那一边：一次无法应答的存储会悄悄解除每一个租户的上限。拒绝才是这里承担得起的那种失败。

**保持原顺序，在 nonce 之后再检查预算。** 这是变更前的形状，它能工作，但它会在调用方唯一能够恢复的那种拒绝上烧掉一次性令牌。而提前消费所对应的安全论据 —— 在触碰密钥之前把重复请求串行化 —— 通过让 nonce 保持在凭据之前（而不是保持在一切之前）已经得到保留。

**在这里既读取预算也扣减它。** 予以否决：扣减是持久写入，而一个通过调用方提供的端口来读取的模块，无法把写入与读取原子地做在一起。非原子地做，恰好会产生预算本要防止的那种重复花费。扣减仍归拥有存储的调用方，而 `chargeRun` 在会透支时拒绝且不扣除任何东西，因此在拒绝时停止的调用方不会留下花掉一半的额度。
