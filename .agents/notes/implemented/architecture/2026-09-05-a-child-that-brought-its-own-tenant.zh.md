# Agent Note: A child that brought its own tenant

Status: implemented

[English](2026-09-05-a-child-that-brought-its-own-tenant.md) | 中文

## Problem

边界页的第六条运行时契约说：子 agent 继承父运行在账户、工作区、工具、token、时间与并发上的授权的一个子集，且子运行的创建不得扩大其中任何一项。token、时间与并发已经被强制执行。账户没有，租户也没有。

针对已启动运行时的一次探查显示了这要付出什么代价。一个其声明指名了不同租户、不同账户的子运行启动了，打开了**那个**租户的凭据，花掉五百个 token —— 而被计费的租户是父运行的那个。子运行的租户一分钱也没被记。

每一部分都在正确地做自己的事。`dsh-run-ledger` 从父运行的记录里为子运行拨款，并把它的花费结算回去。`dsh-credential-vault` 打开声明所指名的那份凭据，只在声明与信封不一致时才拒绝。两者都不知道对方的主体，而它们之间也没有任何东西把两者比对过。

可达性是有界的：身份在断言的签名之内，因此这需要控制平面去铸造这样一个子运行。这让它与会话冲突属于同一类 —— 一个运行时应当拒绝而不是吸收的控制平面错误；而吸收它，就是把一个租户的钱挪到另一个租户的工作上，且两边都不留记录。

## Decision

`admitRun` 增加一个 `findParentIdentity` 端口，并在 `lineage` 阶段拒绝其租户或账户与父运行不同的子运行。

这项检查跑在额度之前。一个并非其父运行子集的子运行，不该去查询一份它无权动用的额度；而且与会话检查一样，它先于 nonce，因此不会为一个并非调用方造成的冲突烧掉任何一次性的东西。

这个端口接收父运行的 run id，而不是指名它的那份声明，因为它只在一次运行确有父运行时才被询问 —— 一个根本无法为根运行调用的签名，好过一个必须自己再检查一次的签名。

一个本部署并不认识的父运行会回答 `undefined`，并被放过。没有记录的父运行就是没有额度的父运行，而额度查找本来就会报告这一点；在那里发明一个世系拒绝，只会掩盖真正的理由。

这条规则被收窄到运行时真正能够裁定的范围。租户与账户是可裁定的，因为父运行各自只持有一个，而一对之中任何一个都不是另一个的子集。工作区授权不是：一个在更窄工作区里干活的子运行是合法的，而这里没有对包含关系建模，拒绝一切差异会把合法的那种和不合法的那种一起拦下。这个缺口被明说出来，而不是被糊过去。

## Consequences

一个扩大其父运行授权的子运行，会在它被铸出来的地方就被拒绝，早于任何占用被取走，也早于它的凭据被打开。持久的运行记录携带它被准入时所用的账户，因此这项检查从唯一能挺过重启的地方读取父运行的身份。

域版本从 3 走到 4：版本 3 的运行记录说不出它的子运行可以指名哪个账户。

## Alternatives considered

**拿父运行的账本记录去比对。** 它在内存里，而且本来就为了额度被读取，但它不持有任何身份 —— 账本刻意只知道运行与额度，不知道租户。给它加上身份，会让那份算术拥有一个它并不需要的主体。

**把不同的工作区授权也拒掉。** 那会补上契约里点名的第三项授权，同时也会连带拒掉合法的收窄场景，而没有任何办法把两者区分开。有了包含关系模型它就可裁定了；而现在没有。

**交给保险库去抓。** 它本来就会拒绝一个其租户与声明不同的信封 —— 而这里声明与信封是一致的，因为子运行如实地指名了它自己的租户。不一致的是子运行与它的父运行之间，而那是任何单独一部分都看不见的。
