# Agent Note: 池根目录位置上的一个链接

Status: implemented

[English](2026-09-04-a-link-where-a-pool-root-goes.md) | 中文

## Problem

`openRuntimePool` 会容忍 `EEXIST`，好让第二次运行加入先前某次运行造出的池，然后用一次显式的 `chmod` 施加 `0o700`。而 `chmod` 会跟随符号链接。

于是被植入在池根目录位置上的条目，会被当作那个池接受：模式修改落到了链接的目标上，而该调用把那条路径当作自己刚刚造出的一个全新私有目录返回。那条路径会成为提供方进程的 `HOME` 与工作目录，因此租户的凭据会被写进去。用构建产物实跑一遍：一个指向另一个目录的符号链接被接受了，目标的模式从 755 被悄悄改成了 700。

危险的目标是另一个租户的池根目录。它的属主与本运行时所属的账户相同，因此这次 `chmod` 会成功 —— 而换成陌生人的目录，它会以 `EPERM` 失败。唯一没有任何附带防御的那种情形，恰恰就是本包存在所要阻止的跨租户重定向。

[docs/defensive-patterns.md](../../../../docs/defensive-patterns.zh.md) 两次点名了这个模式：一次在解链接形状路径下，一次在可预测路径招致符号链接竞争下。池根目录按设计就是最大程度可预测的：名字是租户、提供方与账户的摘要，而且必须如此，因为第二次运行正是靠重算它来找到自己的池。

## Decision

在池所在位置上已经存在的东西，必须是一个真正的目录。`lstat` 描述的是那个条目本身，而不是它指向什么，因此符号链接会被看见；任何不是目录的东西都会被具名拒绝。

这项检查放在创建之后，而不是之前。先检查会是一次竞争 —— 在看过与 `mkdir` 之间，那个条目可以被换掉 —— 而 `mkdir` 要么彻底赢下这次创建，要么报出 `EEXIST`，随后的 `lstat` 描述的就是当时真正在那里的东西。

这次拒绝抛的是 `Error`，而不是本函数为其参数所抛的 `RangeError`。调用方并没有传错什么；是文件系统里放着一个并非这个池的东西。

## Consequences

一个被植入的链接会让这次运行失败，而不是把它重定向，而它的目标保住自己的权限。

本包关于池基目录的已知限制，比原先更窄也更准确。一个另一个账户可写的基目录，仍然会在一种情形下击穿它 —— 该账户创建、而本运行时拥有的一个真实目录，与先前某次运行留下的无法区分 —— 但链接或任何非目录都会被拒绝，而属主是别人的目录会让模式修改以 `EPERM` 失败。

## Alternatives considered

**把 `lstat` 放在 `mkdir` 之前。** 那读到的是它随后并不持有的状态：攻击者可以在检查与创建之间替换那个条目。放在创建之后检查，把窗口收窄到 `mkdir` 自己所裁定的结果。

**像 defensive-patterns 页面对临时路径那样，解掉链接然后继续。** 一个陈旧的临时文件归本包清理；而部署的池基目录里的一个链接不归它，悄悄删掉它会毁掉那次尝试的证据，同时把部署真正的问题 —— 一个可写的基目录 —— 原样留在那里。

**改用 `realpath` 解析路径并检查是否被包含在内。** 那回答的是另一个问题，而且它会接受一个恰好仍留在基目录之内的链接。两个租户的池根目录都在基目录之内，因此包含性并不能把它们分开。
