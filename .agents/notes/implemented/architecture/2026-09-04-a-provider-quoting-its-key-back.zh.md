# Agent Note: 一个把自己密钥引述回来的提供方

Status: implemented

[English](2026-09-04-a-provider-quoting-its-key-back.md) | 中文

## Problem

[Candy 运行时边界](../../../../docs/candy-runtime-boundaries.zh.md)写道，提供方进程的 stdout、stderr、退出状态、结构化输出与诊断文本「都经由有界、脱敏的适配器解析」。Claude CLI 这条路由两样都不是。界定它是[它自己的那篇笔记](2026-09-04-a-piped-stream-is-the-callers-to-bound.zh.md)；这一篇是另一半。

终止 `result` 帧的 `result` 文本会原样成为失败消息。用一个写着 `authentication failed for sk-ant-…` 的帧驱动适配器，产出的 finish chunk 原封不动地带着那个字符串，因此一个把自己凭据引述回来的 CLI —— 在一次认证错误里，或者在任何回显自身环境的诊断里 —— 会把租户的密钥放进会话日志，并摆到模型面前。

共享的适配器约定测试套件本来就断言：一次失败的运行不会发出任何包含该秘密的 chunk，而 `dsh-llm-claude-cli` 也在跑它。那条断言之所以通过，是因为录制到的 fixture 里没有那个密钥，而不是因为有什么东西把它去掉了。一条靠 fixture 而不是靠机制成立的测试，会一直通过下去，直到提供方的文本变了那一天 —— 而那时它失败在生产里，而不是在 CI 里。

## Decision

适配器把被注入的凭据从它发出的失败文本里替换掉。它是唯一能做这件事的地方：密钥在它手上，而 `dsh-claude-cli-protocol` 在不知道这个秘密的情况下翻译帧。

只有诊断文本会被改写 —— 失败的 message 与 code。模型输出是租户自己的内容，悄悄改写会毁掉一个关于密钥长什么样的合法回答。这次替换是对字面秘密做 `split`/`join`，而不是用模式匹配，因此不需要转义任何密钥，也不会误伤别的东西。

不为空密钥加守卫。`claudeCliEnvironment` 在构建 spawn 规格时就会拒绝一个空密钥，而那发生在任何 chunk 存在之前，因此那条不可达分支只会是无法测试的，而不是防御性的。

## Consequences

约定套件的脱敏断言在这条路由上现在靠机制成立。一条引述了密钥的提供方诊断，会带着 `[redacted]` 抵达调用方，消息的其余部分完整保留 —— 那正是运维人员诊断这次失败所需要的。

## Alternatives considered

**在 `dsh-claude-cli-protocol` 里、`mapFinish` 旁边脱敏。** 那个包翻译线格式帧，并且刻意对凭据一无所知；把秘密交给它去擦洗，等于为了在适配器里省下一层包装，而扩大一个纯翻译器所知道的东西。

**对每一个 chunk 都脱敏，包括模型文本。** 那关闭的是一条并非跨租户泄漏的路径 —— 租户自己的密钥出现在租户自己的转录里 —— 代价是毁掉合法输出，并扫描每一个增量。

**依赖约定套件，什么都不改。** 正是那个套件让这个问题浮出水面，而它当时是通过的。让一条安全断言继续搁在某个 fixture 的内容上，正是这篇笔记要消除的那种失效方式。
