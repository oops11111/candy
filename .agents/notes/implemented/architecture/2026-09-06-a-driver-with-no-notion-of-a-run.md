# Agent Note: A driver with no notion of a run

Status: implemented

English | [中文](2026-09-06-a-driver-with-no-notion-of-a-run.zh.md)

## Problem

[No one mints an assertion](2026-09-06-no-one-mints-an-assertion.md) gave `RunScheduler.startChildRun` a way to mint and admit a run for a delegated child, scoped to the one case needing no new authentication — a child restating its already-verified parent's identity. Nothing called it. `dsh-subagent`'s in-process one-shot driver creates a child agent through `ctx.agents.create()` with no notion of a Candy run at all, and its only lifecycle events — `subagent/start`, `subagent/end` — fire after the child is already published, which is too late: minting a run is asynchronous, and a child that started making model calls before its run finished opening could spend before anything bounded it, or worse, run entirely unbounded if the mint later failed and nothing had blocked its first request.

The same package-boundary rule that shaped `dsh-tenant-preset-policy`'s relationship with `dsh-agent-presets` applied again: `dsh-subagent` is a general-purpose Harness package other compositions load with no Candy concept at all, so the fix could not teach the driver about tenants, budgets, or assertions directly.

## Decision

`dsh-subagent`'s `SubagentRuntime` gained one generic extension point: `onBeforeDelegate(hook: ChildDelegationHook): () => void`, where `ChildDelegationHook = (parent: Agent, childId: SessionId) => Promise<void> | void`. Hooks are held in an `AnonymousEntries` registry (the same idempotent-disposer primitive `AgentPresets.guard()` and `ToolRuntime.guard()` already use) and run in registration order through `prepareDelegatedChild(parent, childId)` — a public method the driver calls, awaited, before `ctx.agents.create()`. `childId` already exists at that point: `startInProcessRun` computes it via `brandString<SessionId>(randomUUID())` before creation specifically so a pre-creation hook has something to name the child by. A hook that throws or rejects aborts the delegation entirely — since nothing has been created yet, there is nothing to roll back, unlike a guard's `string | undefined` refusal shape, which fits a decision with no asynchronous setup to run first.

This differs from `AgentPresets.guard()` in kind, not just name: a guard answers a synchronous yes/no with no side effect, while a pre-delegation hook performs asynchronous work (minting and opening a run) whose completion the caller must wait on before proceeding. `subagent/start`/`subagent/end` were considered and rejected as the hook point for exactly the race described above: both fire after publication, so an async mint hung off either would let the child's first request race the run's own admission.

`dsh-run-delegation` is the new Candy-owned package that composes the two: a function plugin (`name`/`inject`/`Config`/`apply`, no service, no default export) whose `Config.childBudget` is a fixed `RunBudget` requested for every delegated child. Its hook calls `RunScheduler.startChildRun(parent.id, childId, () => config.childBudget)` and throws a descriptive `Error` when the parent's session resolves to no single usable run (claimed by several open runs, or its account revoked) or when the mint succeeds but admission or the ledger refuses to fund the exact request (the parent's tenant allowance exhausted, or its own remaining allowance short of `childBudget` in one dimension). A parent with no open Candy run at all — no run for `startChildRun`'s own `findSessionRun` to resolve — is left alone, matching `RunScheduler.tenantOf`'s and `dsh-tenant-preset-policy`'s existing "not this runtime's to fund" default.

The rejection-formatting functions treat the deep admission-stage union narrowly rather than exhaustively. A minted child's claims are copied from its own parent's already-admitted record and carry a freshly generated run id and nonce, so most of what `RunRejection`/`RunLedgerRejection` names guards a forged, replayed, mismatched, or stale token this call site never produces; those branches are marked `v8 ignore if` rather than exercised with fabricated scheduler-internal states, since constructing them would test `dsh-run-admission`'s and `dsh-run-ledger`'s own already-covered logic, not this package's. Two outcomes are reachable and named exactly — the tenant's allowance exhausted, and the parent short of the configured request — and admission's `session` stage is reachable through the one case the already-funded check below cannot recognize, so the generic tail names that stage rather than pretending it cannot happen.

## Consequences

A Candy deployment composing `dsh-subagent` + `dsh-run-scheduler` + `dsh-run-delegation` now opens a real, funded, parented run for every in-process one-shot delegation before the child agent exists. The child's own model calls meter against that run exactly like a root run's, and its unspent remainder returns to the parent when the child settles — the symptom that motivated this work, `dsh-claude-cli-route` refusing a delegated child's session outright with `RUN_NOT_OPEN`, no longer occurs for a deployment that loads this plugin. Any other `dsh-subagent` deployment — one with no Candy run concept at all — is unaffected: the hook registry is empty until something registers into it, and the driver's own behavior and tests are unchanged.

Real-composition tests in both packages prove the wiring: `dsh-subagent-spawn-in-process`'s suite proves a registered hook runs before the child is created and sees the parent and the child's future id, runs several hooks in registration order, refuses the delegation with no orphaned child when a hook throws, and stops being consulted once disposed; `dsh-run-delegation`'s suite boots a real scheduler (real admitted runs, a real SQLite-backed control-plane store) alongside the real `SubagentRuntime` and its shipped spawn provider, and proves a delegation funds the child from the configured budget and parents it to the delegating run, refuses the delegation when the parent cannot afford the exact request or is already exhausted, refuses it when the parent session is claimed by several open runs or its account is revoked, and leaves a parent with no open Candy run unrestricted. `dsh-subagent`'s own continuation suite proves the epoch rule against a real continuable child driven to settlement and back: the hook runs twice for one durable child — once for the fresh creation, once for the cold resume, each before that epoch's agent exists — and a hook that refuses a continuable start leaves no child behind.

Continuable children are wired to the same hook, one epoch at a time. The continuation manager consults it from `materializeTracked` — the one function behind both a fresh continuable creation and a cold resume — because a dormant child released its epoch-scoped resources when it settled, and [a run is renewed only while this runtime holds its session](2026-09-06-a-lease-that-only-counted-down.md), so the run that funded one epoch is gone by the time the next begins. Preparing on every epoch means the consumer sees a child whose previous run may still be open, within the window between settling and the lease lapsing: `dsh-run-delegation` therefore leaves a child that already resolves to one open run with the run it has, since a second run for one session is refused at admission.

Out-of-process product providers (`dsh-subagent-claude-code`, for instance) are still not wired and delegate without a Candy run funding them — see the package's own Known Limitations.

## Alternatives considered

**Hang the mint off `subagent/start` instead of a new pre-creation hook.** Rejected: `subagent/start` fires after the child agent is already published and its lifecycle handed to the caller. An asynchronous mint begun there races the child's own first turn, which `drivePublishedRun` schedules immediately after `ctx.agents.create()` resolves — a child could make its first model call before a run existed to bound it, and a mint that later failed would have no created-but-unpublished state to roll back, unlike the pre-creation hook's clean refusal.

**Give the guard's `string | undefined` shape to the delegation hook too, keeping it synchronous.** Rejected: minting and opening a run needs an async `ControlPlaneStore` write and, on the ledger path, a queued chain operation — there is no synchronous answer to give. Forcing synchronicity would mean either blocking the hook on a pre-fetched cache (state that could go stale between fetch and use) or moving the actual mint to some other, still-unaddressed hook point, which is the same problem restated.

**Fold the child-run-opening logic directly into `dsh-subagent-in-process-driver`.** Rejected: the driver is a general-purpose Harness package with no notion of a Candy run, tenant, or budget; teaching it those concepts would repeat the exact mistake `AgentPresets.guard()` was built to avoid for the preset roster, and would make every non-Candy consumer of the driver carry code paths it never exercises.

**A per-call computed share instead of one fixed `config.childBudget`.** Considered, since a real deployment may want to fund a background research task more generously than a quick lookup. Rejected for this slice: no current consumer needs it, and `startChildRun`'s own `share` parameter already accepts an arbitrary function — a deployment wanting a computed share composes its own hook against `onBeforeDelegate()` directly rather than this package growing a policy language to express it. A fixed allowance is the smaller, evidence-backed default; per-task shares are deferred until a consumer needs one.
