# Agent Note: 一个活过进程的 nonce

Status: implemented

[English](2026-09-07-a-nonce-that-survives-the-process.md) | 中文

## 问题

Candy 校验执行断言后,会在一个 `RunScheduler` 所拥有的 map `RunReplayStore` 中消费其 nonce。这让一个进程内的两次同时调用成为不可分割的决定,但重启会忘掉每一个仍然有效的断言,两个运行时进程也会各自准入一份副本。准入端口承诺的是整个部署的一次性决定;生产组合提供的却只是一个对象的一次性决定。

持久控制平面领域无法用原有 API 修复它。`KvTable.get` 是该进程打开领域时加载的快照,而 `putRecord` 是无条件 upsert。读取、await 再写入会在跨进程时重新制造重放窗口。JSON 的单文件与逐记录布局也没有一种可移植锁协议,能把比较与替换做成同一个决定。

## 决定

KV seam 现在有一个可选的 `compareExchangeRecord` 操作。它把一条持久记录与预期 JSON 值比较,只在相等时替换或删除,并从同一个原子操作返回当前值。`KvTable.compareExchange` 通过领域写入链暴露它;所选后端没有该能力时以 `facet-unsupported` 拒绝,不存在快照回退。

SQLite 在 `BEGIN IMMEDIATE` 到 `COMMIT` 的事务中实现该操作。因此比较、条件插入/更新/删除与当前值读取会跨进程持有同一个写事务。JSON 省略该能力,而不是声称自己能提供并不存在的保证。

控制平面领域升到版本 8,并拥有 `spent_nonces`。其键是 `run-replay` 以长度为前缀构造的租户加 nonce 键的 SHA-256 摘要,既保持逐记录路径安全,也不改变原有碰撞边界。值是断言过期时间。准入会原子插入缺失记录、拒绝尚未过期的记录,或替换已经过期的记录。清扫只会在某个过期值仍然恰好是当前值时删除它,所以一个进程不能擦掉另一个进程刚建立的新预留。

`RunScheduler` 现在从 `ControlPlaneStore` 提供 `spendNonce`,不再拥有 `RunReplayStore`。内存类仍作为小型契约实现保留,供库测试以及明确只运行一个进程的消费方使用。

## 后果

崩溃前消费的 nonce 在运行时重启后仍然是已消费状态。共享同一 SQLite 控制平面数据库的两个进程无法同时准入相同租户与 nonce。早先断言过期后可以再次使用相同 nonce,且清理不会以竞态把一个较新的断言移出存储。

生产控制平面领域如果路由到 JSON,现在会在第一次 nonce 决定时以 `facet-unsupported` 失败。这是有意的:不会用不具备能力的后端上的可用性去交换重放漏洞。SQLite 锁竞争也会作为准入操作失败透传;本次改动没有加入隐藏重试策略。

控制平面领域从版本 7 升到 8,遵循仓库的预发布丢弃策略。旧存储没有持久重放历史;若读取它的其他记录,却假装 nonce 表是完整的,就会重新放行升级前签发的断言。部署上线前必须迁移或明确替换该存储。

测试通过两个独立后端连接钉住 SQLite 原语,并用真实 Loader 组合证明:一个已消费 nonce 在完整控制平面重启后仍被拒绝,且只在过期时才重新可用。

## 考虑过的替代方案

**保留调度器 map,并要求单进程。** 拒绝,因为 Debian 部署预计会重启和扩容;断言的 audience 绑定到运行时服务,而不是某一个 JavaScript heap。

**先 `loadAll`,再 `putRecord`。** 拒绝,因为两个调用之间的 await 正是双重准入窗口,而领域的内存快照观察不到另一个进程。

**为两种 JSON 布局都增加文件锁。** 对这个边界拒绝。单文件布局会重写整个单元,逐记录布局则没有陈旧锁所有权协议。生产路径已经配置为 SQLite;在它旁边交付第二套略有差异的进程锁,会为了本任务扩大存储子系统。

**永远保留 nonce 键,只要求不存在时插入。** 拒绝,因为重放契约按断言生命周期限制保留时间,而由租户控制的永久键会产生无界存储。compare/exchange 允许安全的过期替换与精确值清理。
